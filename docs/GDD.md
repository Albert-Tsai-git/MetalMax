## 1. 游戏概念

### 一句话介绍

在内海干涸后的盐尘荒原上，玩家驾驶一辆由旧部件拼成的战车，探索遗迹、承接高危委托、收集零件，并通过改装决定自己的战斗方式。

### 核心体验

玩家从一辆能力有限的轻型战车出发，在荒原和遗迹中寻找部件与线索；每次改装都要在火力、防护和载重之间取舍。主要成长来自玩家理解部件组合并为下一次远行做好准备。

### 类型与参考范围

- 类型：单机、回合制、队伍与车辆成长 RPG。
- 参考方向：废土公路探索、车辆部件改装、回合指令战斗、区域委托与强敌挑战。
- 原创边界：世界名词、角色、剧情、敌人、车辆外形、音乐、UI 和素材均为本项目原创；只借鉴宽泛类型机制，不复用既有作品资产或角色设定。

### 项目代号与故事提案

**项目名暂留空。**以下是便于继续设计的原创剧情提案，尚未确认：

> 多年前，一套调节内海水位的地下泵网突然停摆，留下被盐层覆盖的盆地和沿旧公路迁徙的聚落。玩家扮演受雇的回收驾驶员，追查一串来自停运泵站的求救信号。随着战车逐步改造，玩家发现信号并非求救，而是一套仍在运行的水权分配协议。不同聚落希望把泵网交给自己控制，玩家需要决定如何处理它。

叙事基调：荒凉环境、务实的人情关系、适量黑色幽默。主线主题提案：稀缺资源由谁维护、使用和分配。

### 范围分层

- **当前原型**：灰盒野外移动、随机遇敌、单场战斗、战后奖励与临时修理入口。
- **最小可玩闭环**：离开据点、探索一个危险区域、进入战斗、取得奖励、安装或升级部件、再次出发，并能保存进度。
- **垂直切片目标**：一座据点、一个荒野区域、一座短迷宫、一条短任务线、一个高危目标、少量普通敌人、一辆可改装战车和约 20 分钟可试玩流程。
- **展示版候选范围**：在试玩闭环稳定后，把高危目标扩充到 3 个，并加入对应委托和区域奖励。
- **完整游戏目标**：多区域、多聚落、多条委托线和约 15 小时主线。按实际团队人数和内容制作速度重新估算。

## 3. 设计支柱

1. **战车就是主要成长角色**：改装应改变属性、战术选择和外观。
2. **探索路线由玩家选择**：区域提供不同危险度、资源和目标，玩家可自行决定准备程度。
3. **强敌有明确动机和回报**：高危目标关联地区故事、战斗机制和有价值的装备或资源。

所有新增系统应至少支撑其中一条支柱；首版不需要为了“像 RPG”加入没有验证价值的复杂子系统。

## 4. 核心循环

```text
在据点获取委托、修理和配装
       ↓
选择路线并进入荒野或遗迹
       ↓
普通遭遇 / 可见高危目标
       ↓
回合战斗、消耗弹药与装甲、争取胜利
       ↓
获得金钱、经验、素材或部件
       ↓
回到据点修理、升级、换装并解锁下一段路线
```

- **短循环（约 1–3 分钟）**：野外移动 → 遭遇 → 战斗 → 拾取战利品。
- **中循环（约 15–30 分钟）**：准备出发 → 探索区域 → 消耗资源 → 完成委托或撤回据点。
- **长循环（数小时）**：追踪高危目标、取得关键部件、开放新路线并推进主线。

**闭环验收条件**：战斗所得能够改变战车配置；改装结果能在下一场战斗中体现；战斗结果、货币、弹药和装备状态能正确保存在读档中。

## 5. 玩法系统

### 5.1 探索与遭遇

- 地图采用据点、荒野和遗迹组成的区域式结构，各区域可独立加载。
- 普通敌人在设定了危险度的遭遇区域中随机出现；高危目标在地图上可见或通过委托标记。
- 进入战斗前记录野外位置；战后返回原位置。
- 刚结束战斗后提供短暂安全距离，避免连续触发战斗。
- **待定**：野外受控单位是角色、车队图标还是可见战车。当前 `FieldPlayerController` 是胶囊角色的水平移动原型，没有车辆驾驶物理或战车地图外观。
- **平衡要求**：普通遭遇应提供资源和风险，不得成为阻断主线的强制刷级门槛；保留降低遭遇率或安全路线的设计空间。

### 5.2 回合制战斗

#### 战斗流程

1. 玩家为每名存活队员选择行动。
2. 敌人生成行动意图。
3. 全体行动按速度从高到低结算，同速时随机排序。
4. 检查胜利、全灭或逃跑，并发放结果。

当前设计以**每名角色每回合一次行动**为默认规则。C 装置额外行动属于后续平衡项；当前代码有 `actionsPerTurn` 数据，但战斗指令流程还没有消费该数值。

#### 玩家行动

- 乘车时：选择可用的主炮、副炮或 SE 武器及目标。
- 步行时：基础人类攻击。
- 其他行动：上车、下车、防御、逃跑。
- 技能、消耗品、状态异常和部位瞄准列为后续系统，不计入最小切片要求。

#### 敌人与胜负

- 原型敌人 AI 为随机选择一名玩家攻击；垂直切片扩展为少量可读行为，例如冲锋、集火、召唤或蓄力攻击。
- 武器范围支持单体、小组和全体；范围内敌人数量、目标确认方式和演出仍需迭代。
- 胜利奖励经验和 G；高危目标另给委托奖励或专属部件。
- **败北规则方向**：正式流程返回最近据点并扣除部分金钱；当前原型将队伍恢复并扣除一半金钱。最终惩罚力度待试玩确认。

#### 数值草案

```text
伤害 = max(1, floor((攻击 - 防御 / 2) × 随机(0.9, 1.1)))
命中率 = clamp(攻击方命中 - 目标回避, 5%, 99%)
```

- 防御行动将本次伤害减半。
- 属性克制倍率暂不列入最小切片；待敌人属性、提示 UI 和可读性设计确定后再加入。
- 平衡表需覆盖前期武器、常规敌人、战车 SP、弹药消耗和维修成本。

### 5.3 战车与部件改装

| 部件 | 设计作用 | 主要取舍 |
|---|---|---|
| 底盘 | 决定武器孔类型/数量、基础防御和座位 | 轻型机动与重型火力容量 |
| 引擎 | 决定载重上限 | 重量、价格和升级空间 |
| C 装置 | 提供命中、回避加成；未来可调整行动数 | 电子性能与载重成本 |
| 主炮 | 高威力单体攻击 | 弹药、重量和命中 |
| 副炮 | 连射或范围攻击 | 单发威力与覆盖范围 |
| SE | 导弹、火焰等特殊武器 | 强效果、有限弹药与较高重量 |
| 装甲 SP | 战车的吸收伤害资源 | 装甲越多，可分配给其他部件的载重越少 |

规则草案：

- 部件总重量加装甲重量不得超过引擎载重，否则战车不能行驶。
- 可用载重转换为装甲：`1 吨 = 100 SP`；具体保留几位小数由数据表决定。
- 受击先扣 SP；溢出后有概率损坏一个仍可用的部件。损坏部件性能减半，再次损坏后大破失效。
- 所有关键部件失效时，战车失去战斗能力，乘员被迫下车。
- 改造提升部件性能并增加重量或费用；引擎改造可增加载重。
- 换装后更新车辆外观；底盘模型提供命名固定的武器挂点。
- 商店库存、背包、部件拆装确认和车库菜单属于垂直切片待做内容。

### 5.4 队伍与成长

| 角色职责 | 玩法定位 | 规划状态 |
|---|---|---|
| 驾驶员/猎人 | 战车主操作者，负责驾驶与战斗指令 | 原型队伍已有一名乘车角色 |
| 机械师 | 修理、维护和战车相关支援 | 原型队伍已有一名步行角色；战斗技能待做 |
| 战士 | 人类武器与步行战斗专长 | 长期角色方向，原型队伍未加入 |
| 犬类伙伴 | 探索或战斗辅助 | 待定，不进入首个切片范围 |

- 长期成长方向：等级、基础属性和少量角色技能；技能点系统尚未定案。
- 首个切片限制为两名队员、一辆玩家战车；更多队员、宠物和多车队伍在闭环验证后再确定。
- 人类武器、个人装备、队伍编成和战斗中使用物品尚未实现。

### 5.5 任务与高危目标

- 委托在据点获取，提供目标、地区、报酬和必要线索。
- 普通任务用于认识地区、获取补给和介绍人物；高危目标任务构成区域的主要挑战。
- 每个高危目标至少有：原创名称、活动区域、行为特点、弱点或战术提示、报酬、与当地人物的联系。
- 原型数据目前只有敌人悬赏标记和金额字段；任务接取、追踪、结算及目标图鉴界面待做。

### 5.6 经济、物品与存档

- 货币名暂用 G；收入来自战斗、委托和出售素材。
- 主要支出：修理、弹药、改造、购买部件。每次出行要让消耗与回报形成可理解的选择。
- 背包、商店、素材合成暂不进入最小战斗原型；车库购买、拆装和修理属于垂直切片必要功能。
- 存档拟使用 JSON；部件、敌人和任务通过稳定 ID 关联数据资产，避免直接序列化 Unity 对象引用。
- **待做**：存档槽、自动存档时机、版本迁移、退出/继续流程和异常中断恢复。

## 6. 世界与内容结构

### 区域结构

| 区域 | 功能 | 首个切片 |
|---|---|---|
| 起始据点 | 任务、商店、修理、改装、角色对话 | 需要一个可用的车库闭环 |
| 荒野 A | 路线选择、普通遭遇、隐藏补给、高危目标线索 | 需要一片小地图 |
| 废弃泵站/工厂 | 短迷宫、资源风险和剧情线索 | 需要一个短流程和一个强敌 |
| 后续区域 | 新聚落、地形和委托线 | 不进入首片 |

场景方向为据点、野外、迷宫和战斗独立场景；原型使用 `Field`、`Battle` 场景名进行切换。具体制作时应在 Unity Build Settings 中确保场景清单一致。

### 内容制作基准

- 每个区域至少提供一个路线/资源取舍和一个可记住的地标。
- 普通敌人承担资源消耗和世界生态说明；高危目标承担主要战术检验。
- 部件奖励应对应可见的配装选择，不以纯数值递增作为唯一奖励方式。
- 地图、敌人和部件数量按垂直切片验证后的实际生产速度扩展。

## 7. 美术与音频

### 美术方向

- 方向：Low-poly 3D、固定俯视构图、Toon/简化材质、低饱和盐尘色系和高饱和功能色点缀。
- 车辆剪影要一眼区分轻型、重型和特殊用途；功能部件换装后在战斗和车库界面都可读。
- 初期预算建议：战车 3k–8k 三角面、角色不高于 5k、普通敌人 2k–10k；作为制作参考值，需依据目标机实测调整。
- 贴图建议 256–1024px，优先共用调色板/材质并控制材质数量。
- 命名建议：`TNK_` 战车、`WPN_` 武器、`CHR_` 角色、`ENM_` 敌人、`ENV_` 环境。
- Blender → FBX 流程统一单位、应用变换、轴向、枢轴、挂点和贴图相对路径；需用真实导入结果核对，而不是只看 Blender 视窗。

### 音频方向

- BGM：据点、荒野、遗迹、普通战斗、高危目标战斗、胜利/失败。
- SFX：引擎、移动、装弹、炮击、命中、部件损坏、大破、修理、UI 和环境氛围。
- 首片先制作必要事件音效和一首核心战斗曲；素材需留存来源及许可。

## 12. 主要风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 15 小时主线与大量区域超出产能 | 项目范围持续扩大 | 先按 M0/M1 验收；M1 试玩后再按内容生产速度估算完整规模 |
| 随机遇敌密度过高 | 探索被打断、玩家疲劳 | 按区域设置遭遇率，提供安全距离和路线差异，试玩后调数值 |
| 战车被毁导致流程卡死 | 资源不足或战斗软锁 | 提供步行撤退、紧急救援或据点恢复之一；规则待设计并纳入失败路径验证 |
| 装备选择只有单一最优解 | 改装失去意义 | 让重量、弹药、火力、防护和维修费用形成可理解取舍 |
| 数据资产引用与存档脱节 | 改名或更新内容造成存档损坏 | 存档使用稳定部件 ID，建立版本号与迁移规则 |
| 美术资产重复制作 | 产量不足 | 模块化底盘/武器/挂点、复用材质和环境套件 |
| 尚未建立版本管理 | 两方协作改动无法追溯或回退，二进制资产易冲突 | 初始化 Git + LFS（或等效方案），配置 Unity 专用 `.gitignore` 与二进制资产规则 |
| IP 或素材授权不清 | 商业发布风险 | 保持原创设定和素材；记录第三方资产来源与许可证 |
