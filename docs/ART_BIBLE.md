# 美术基线与首批资产计划

> 项目：原创废土战车 RPG（暂定）  
> 版本：v0.1　|　日期：2026-09-27  
> 状态：制作基线提案；车辆外观与世界色彩需在首轮 Unity 画面检查后定稿。

## 1. 目标

建立一套可持续制作的原创美术规则，让 Blender 资产在固定俯视 2.5D 镜头下轮廓清楚、换装可辨，并能逐步扩展到野外、据点、敌人和界面。游戏机制仍以 GDD 和机制实现为准；此文档只定义表现和资产接口。

## 2. 视觉支柱

1. **远看先读轮廓**：战车、敌人与地标用外形区分，细节不能代替剪影。
2. **旧世界被重新利用**：板件有维修和拼装痕迹，但不把每块表面都做成锈蚀噪点。
3. **火力与功能一眼可辨**：主炮、副炮、引擎、装甲、可交互物使用不同体块与色彩层级。
4. **镜头下仍可读**：重要形状和交互提示在俯视镜头缩小后保留；低优先级装饰可以省略。

## 3. 风格与色彩

- **风格**：低多边形 3D、硬表面大形、分面明暗、简化 Toon 光照；避免写实军武比例与写实表面噪声。
- **主环境**：盐白、浅沙、灰褐、暗岩；大面积颜色低饱和，地标与路线用明度或形状区分。
- **战车基准色**：灰青绿/旧橄榄绿板件、沙色替换装甲、煤黑轮胎与机械缝隙。
- **识别强调色**：少量橘红用于回收标记、危险设备或可交互提示；不要把全车做成高饱和橙色。
- **材质原则**：优先共用调色板/材质；轮胎、金属、玻璃和发光提示允许少数独立材质。锈迹集中在边缘、紧固件和补丁处。
- **灯光**：场景基准采用偏暖日光、冷灰阴影；战斗与车库中的关键装备应有轮廓分离，不靠纯黑描边解决所有可读性。

## 4. 首个战车概念：轻型回收车（暂名）

概念参考图：[TNK_Light_Rover_Concept_v01.svg](../UNITY/Assets/Art/Concepts/TNK_Light_Rover_Concept_v01.svg)

**这是用于首轮建模的提案，不是锁定设定。**它把现有轻型底盘的两个挂点落实为能读懂的外观：`Mount_Main` 装 75mm 主炮，`Mount_Sub` 装 7.7mm 机枪。暂定采用六轮越野车、前置小驾驶舱、后置外露引擎的轮式剪影，方便和重型战车区分；若野外镜头测试后六轮细节不清楚，应优先简化轮组，而非缩小车身主形。

### 体块与识别点

- 紧凑、低矮、前窄后宽；车头有斜面防护和两片深色挡风玻璃。
- 左右各三只大轮胎，轮胎略外露；轮拱和侧裙只包住轮胎上半部。
- 中后段有可见的 V8 引擎罩/排气结构，作为轻型底盘“容易修”的识别特征。
- 中央炮座与炮管属于 `Mount_Main` 可替换模块；机枪独立属于 `Mount_Sub`，不能焊死在底盘网格里。
- 车体用旧青绿为基底，最多两三片沙色替换装甲，橘色标记集中在功能位置。
- 目标首先是稳定剪影、比例和挂点位置；螺栓、刻字、贴花等微细节最后再加。

### 暂定模型尺度与资产合同

| 项目 | 暂定值/要求 |
|---|---|
| 车长、车宽、含炮高 | 约 4.6m × 2.4m × 2.2m（提案；Unity 镜头下再调） |
| 轻型底盘面数 | 3k–8k tris，沿用 GDD 建议并以实际导入画面为准 |
| 贴图 | 先用材质色块；需要纹理时从 512px 起，资产预算 256–1024px |
| 坐标/单位 | 以协作约定为准：Unity 中 1 单位 = 1 米、Y 轴向上、车辆前向 +Z；Blender 导出必须转换到该约定并经 FBX 导入核对 |
| 原点 | Unity Prefab 根原点位于车体中心线与地面的交点，轮胎接地；Prefab 根 Transform 为单位变换 |
| 挂点/武器 | `Mount_Main`、`Mount_Sub` 名称精确；武器枢轴与挂点对齐，炮口本地 +Z |
| 轮子 | 使用稳定轮轴枢轴；如首片不做驾驶动画，可把轮组做成静态装配 |
| 命名 | `TNK_Chassis_Light`；网格可用 `GEO_Body`、`GEO_Wheel_FL` 等描述性子名 |

建议层级（挂点名称必须和现有数据一致）：

```text
TNK_Chassis_Light
├─ GEO_Body
├─ GEO_Engine_V8
├─ GEO_Wheel_FL / GEO_Wheel_FM / GEO_Wheel_FR
├─ GEO_Wheel_RL / GEO_Wheel_RM / GEO_Wheel_RR
├─ Mount_Main
└─ Mount_Sub
```

引擎作为底盘外观的一部分先做固定网格；若机制侧以后需要换引擎外观，再拆成独立挂点或替换插槽，不提前假设现有数据已有引擎挂点。

## 5. Blender 到 Unity 的交付约定

- 按 `docs/COLLABORATION.md` 检查 FBX 单位、轴向转换、已应用变换、原点、挂点名称、贴图相对路径和导入朝向。
- 每个可替换武器独立建模并单独导出；不要在底盘 FBX 中合并武器网格。
- 挂点使用空物体；武器炮口朝本地 +Z。完成一次 Unity 导入核验后，把挂点旋转轴固化为模板。
- 网格优先共用材质槽；玻璃可用不透明冷色和简单高光，避免依赖复杂透明排序。
- 交付至少包含 `.blend` 源文件、FBX、贴图（如有）、预览图、资产 ID 和来源说明。
- 文件命名沿用 GDD 前缀：`TNK_`、`WPN_`、`CHR_`、`ENM_`、`ENV_`。版本号放在归档或导出文件夹，不写入运行时稳定 ID。
- 首轮 Unity 检查要分别看车库近景、战斗尺度和实际俯视镜头；俯视图无法读出挂点的装备应调整轮廓或颜色层级。

## 6. 首片美术资产顺序

| 优先级 | 资产包 | 内容/验收重点 |
|---|---|---|
| P0 | 玩家轻型战车 | 底盘、可辨引擎、六轮剪影、`Mount_Main` / `Mount_Sub`；俯视仍能读方向 |
| P0 | 武器模块 | 75mm 炮与 7.7mm 机枪独立模块；接口位置与 CSV 数据名称对应 |
| P0 | 车库展示台 | 中性灯光、检修地台、工具和少量回收件；能看清换装前后 |
| P1 | 野外地表套件 | 盐壳地面、沙丘边、碎岩、道路/轮迹；同一套材质可组合出可读路线 |
| P1 | 回收物与掩体 | 废弃水管、泵站部件、路障、补给箱、残骸；尺寸和交互状态有明显区别 |
| P1 | 普通敌人 | 变异蚁、炮台虫、野狗；分别用群体/远程/高速剪影区分，不靠换色区分 |
| P2 | 高危目标 | 铁钳巨蟹；用宽轮廓和大型钳/装甲外形做战场焦点 |
| P2 | 轻量 UI 图标 | 主炮、副炮、弹药、装甲、修理、回收标记；小尺寸下保持轮廓辨识 |

Unity 工程位于 `UNITY/`，但当前尚无对应的 Blender 模型或 FBX；此计划只准备制作方向与接口，不把 SVG 概念图当成可直接导入游戏的模型。

## 7. 评审检查表

- [ ] 固定俯视镜头下能迅速看出车头方向、车辆级别和当前装备。
- [ ] 换掉主炮或副炮时，外形和挂点变化清楚，未把武器烘焙进底盘。
- [ ] 车身和地表有足够明度分离，盐地不吞掉浅色装甲。
- [ ] 近景有维修痕迹，远景没有依赖小贴花或细碎法线。
- [ ] Unity 导入检查确认尺寸、朝向、枢轴、挂点和材质均正确。
- [ ] 视觉方案保持原创命名与轮廓，不复制参考作品的标志性造型、涂装或图像。

## 8. 下一步建议

1. 在 Unity 相机视角中放入底盘、主炮和机枪三个灰模，先检查俯视识别度。
2. 锁定车体比例后再制作最终低模与模块武器，不先堆环境资产。
3. 由机制侧提供挂点生成和更换的场景验收入口；美术侧只依赖命名合同，不改机制实现。
4. 根据车库和战斗镜头的真实画面修订尺度、材质预算和色板。
